# `av-wrf`: Cloud-Agnostic Regional WRF Producer Plan

Build a lean, testable regional WRF forecasting producer in `av-wrf` with a pure numerical core and a thin effectful runner inside a pinned Linux OCI container—publishing immutable **Sharded Zarr v3** native model-level forecast stores consumed by `windy-av-layer` (`av-layers`) as `ModelLevelFrame` inputs with zero duplicate soaring science, tiling, or hardcoded regions.

## 1. Scope, Ownership, & Core Guardrails

1. **Strict producer/consumer boundary.** `av-wrf` prepares static geography, initializes and integrates `WRF-ARW`, stages normalized native-model-level Zarr v3 frames, enforces full-horizon and column/CFL admission gates, writes immutable `_ready.json` and `_diagnostics.json` cycle receipts, and triggers `windy-av-layer`. All parcel thermodynamics (`dry-lenschow-1p2-model-levels-v2`), Copernicus GLO-90 subgrid terrain-column refinement, `samples.bin`, `profiles.bin`, and `.pmtiles` stay exclusively in `windy-av-layer`.
2. **Declarative regions in `config/` only (`KISS` / `YAGNI`).**
   - **Phase 1 production scope:** One Linux container architecture (`linux/arm64`, pinned by platform OCI digest), declarative `3 km` regional and fast-pilot products under [`config/products/`](../config/README.md) (listed in [`docs/reference.md`](reference.md)), one frozen physics suite, one primary forcing recipe with fail-closed validation, explicit model selection in `av-layers`, and Day-1 retention, budget alarms, scoped credentials, and rollback.
   - **Deferred until baseline skill and cost are measured:** Additional NH/SH regions (Phase 6), CONUS experiments against operational [NOAA RRFS](https://www.noaa.gov/news-release/noaa-weather-modeling-hits-key-milestone-with-rapid-refresh-forecast-system-debut), `1 km` child nests (`>= 100×100` interior cells), cross-cycle warm land-state splicing, `Auto` model switching, secondary compute backends, and experimental solver engines (`MPAS`, `WRF-JAX`).
3. **Pure numerical core + thin effectful runner.**
   - Pure Python functions over contiguous `float32`/`int32` buffers own domain math, `auto_levels_opt = 2` vertical checks, `RunLock` resolution, exhaustive namelist compilation, stateful `post_frame` + `AccumBaseline` differencing, Arakawa-C destaggering, thermodynamic/wind transforms, and verification math.
   - A small effectful runner handles object storage (`file://` and S3/R2), HTTP mirror downloads, `mpirun` execution, attempt staging, full-horizon promotion, and fail-closed idempotent webhook dispatch (`_dispatched.json`).
4. **Provisional -> Consumer-Owned Contract + Independent Oracle.**
   - `vendor/producer-contract/wrf-zarr-v3.schema.json` starts as `"provisional-phase-1"` in `av-wrf` while `windy-av-layer` completes its v5 cutover; Milestone 1 promotes `wrf-zarr-v3.schema.json` + `createZarrV3Provider` into `windy-av-layer/packages/contracts/` (`scripts/sync_contract.py --from-consumer ../windy-av-layer`).
   - Both sides are verified against an independent `PROJ` (`+proj=lcc +R=6370000`) + analytic thermodynamic oracle (`tests/oracle/reference_cases.py`).

## 2. Canonical Output Format: Sharded Zarr v3 on Native Model Levels (`wrf-zarr-v3`)

`av-wrf` publishes a complete **Zarr v3 (`zarr_format: 3`, [ZEP-0001 / ZEP-0002](https://zarr.dev/zeps/accepted/ZEP0002.html))** store hierarchy directly on WRF's native terrain-following mass levels—mapping 1:1 into `windy-av-layer`'s `ModelLevelFrame`:

- **Store hierarchy per cycle:** Attempt staging under `runs/{product}/{YYYYMMDD}/{HH}/attempts/{id}/staged/` promoted atomically after full-horizon digest verification to `upstream/{model}/{YYYYMMDD}/{HH}/forecast.zarr/` (`zarr.json` root group + 7 coordinate arrays + 22 sharded data arrays = `30` `zarr.json` metadata documents) + `_diagnostics.json` + `_ready.json`.
- **Dimensions & Georeferencing:**
  - `time` (`T` configured lead frames, with `valid_time_unix_s[T]`, `window_start_unix_s[T]`, `window_end_unix_s[T]`), `level` (`K` lowest WRF mass levels), `y` (`nj`), `x` (`ni`).
  - Root `zarr.json` embeds both `crs_wkt` ([GeoZarr](https://github.com/zarr-developers/geozarr-spec)) and the exact `windy-av-layer` `LambertConformalGrid` object.
- **Sharding & Codecs:**
  - **Spec-compliant Zarr v3 codec chain:** `sharding_indexed` (`index_location: "end"`) with inner data codecs `[{"name": "bytes", "configuration": {"endian": "little"}}, {"name": "zstd", "configuration": {"level": 3}}]` (deterministic `zstandard`/`libzstd` C ABI, decoded natively via Node `node:zlib.zstdDecompress` and `zarrita.js`) and index codecs `[{"name": "bytes", "configuration": {"endian": "little"}}, {"name": "crc32c"}]`.
  - **Precision-bounded IEEE-754 mantissa grooming:** `keepbits = 17` on pressures/heights and `keepbits = 15` on temperatures, humidity (`spfh_kgkg`), winds, and fluxes.

## 3. Frozen Phase 1 Scientific, Vertical, & Schedule Baseline

1. **Physics & Dynamics (`convection-permitting-3km-v1.yaml`):**
   - `mp_physics = 8` (Thompson), `ra_lw_physics = 4` / `ra_sw_physics = 4` (RRTMG, `radt = 3`, `slope_rad = 1`, `topo_shading = 1`, `shadlen = 25000`), `sf_surface_physics = 4` (`Noah-MP`, `opt_runsrf = 1, opt_runsub = 1`; rejects `5` per [WRF v4.8.0 Known Problems](https://github.com/wrf-model/WRF/wiki/WRF-V4.8.0-Known-Problems)), `bl_pbl_physics = 1` + `sf_sfclay_physics = 1` (`YSU` + Revised MM5, `topo_wind = 1`, `shinhong_scu_mixing = 0`, `shinhong_nonlocal_flux = false`), `cu_physics = 0`, `gwd_opt = 0` (`gwd_if_nonhyd = false`), `use_theta_m = 1`, `base_temp = 300.0`, `hybrid_opt = 2` (`etac = 0.2`), `diff_opt = 2`, `km_opt = 4`, `diff_6th_opt = 2` (`0.12`), `epssm = 0.3`, `w_damping = 1`, `damp_opt = 3` (`zdamp = 5000, dampcoef = 0.2`), `time_step = 15`, `spec_bdy_width = 5` (`1 + 4`, `bdy_trim_cells = 8`), `interval_seconds = 3600`, `frames_per_outfile = 1`, `history_begin_h = spinup_hours`, `nwp_diagnostics = 1`, `afwa_diag_opt = 1`, `afwa_severe_opt = 1`, `history_interval = 60`, `prec_acc_dt = 60`, `bucket_mm = 100.0`, `bucket_J = 1.0e9`, plus `num_metgrid_levels` and `num_metgrid_soil_levels` bound from `ForcingProfile`.
2. **Vertical Grid (`config/profiles/domains/*.yaml`, detailed in [Science and assumptions](science.md)):**
   - [WRF `auto_levels_opt = 2`](https://www2.mmm.ucar.edu/wrf/site/users_guide/real_initialization.html) + `hybrid_opt = 2` (`etac = 0.2`), `p_top_pa = 5000`, `dzbot_m = 34.0` ([WRF Forum #8325](https://forum.mmm.ucar.edu/threads/increase-eta-level-and-decrease-dzbot.8325/)), `dzstretch_s = 1.11`, `dzstretch_u = 1.06`, `max_dz_m = 850.0` ($\ge 15\%$ thermal-expansion headroom below consumer `maximumProfileGapM = 1000 m`). Verified by `av-wrf check` across every elevation in `DomainProfile.terrain_elevations_m`.
3. **Sensible Air Temperature Semantics (`T` vs `THM`):**
   - Per [WRF Users' Guide Ch. 5](https://www2.mmm.ucar.edu/wrf/users/docs/user_guide_v4/v4.4/users_guide_chap5.html) and [NCAR WRF Forum #5569](https://forum.mmm.ucar.edu/threads/accessing-variables-on-head_grid.5569/), `wrfout` `T` is dry perturbation potential temperature $\theta - T_0$, while `THM` is moist perturbation potential temperature $\theta (1 + (R_v/R_d) q_v) - T_0$. `codecs/wrf_nc.py` cross-checks `potential_to_temp_k(T)` against `moist_thm_to_temp_k(THM, QVAPOR)` on every ingested frame.
4. **Deadline, Cron Arrival Buffer, & Remaining-Horizon Invariants (`core/schedule.py`):**
   - `validate_horizon_policy` enforces `>= 15 min` cron arrival buffer above `source_ready_lag_p95_hours`, `spinup_hours >= 6`, and `map_end_hour - max_cycle_age_hours >= min_horizon_hours`.
